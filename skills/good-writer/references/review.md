# 内容与交付复核

以本次用户要求和课程规范为准，不用自评分代替验收。下面是按需检查的维度，不要求每篇报告逐项展示，也不强制给分。

## 先查会使内容失真的问题

- 区分观察结果、代码机制、作者自述和推测。日志没有记载的修复过程不能从最终实现倒推；范文和旧助手稿不能充当个人经历证明。
- 结论保留条件、比较对象和确定程度。小样本最好结果不等于理论极限，测试通过不等于所有场景可靠，相关现象不自动证明因果。
- 核对影响解释的技术区别。例如协议投递范围与权限隔离、队列与消费者、持久数据与内存状态不能混称。发现具体错误时查当前实现或权威资料，不用流畅改写掩盖错误。
- 保留数值、单位和任务范围。用户要求精简表格时可以移走重复实现细节，但不能删掉改变结论的条件。

## 再查章节是否承担了正确任务

| 维度 | 可以接受的结果 | 需要修订的迹象 |
|---|---|---|
| 知识理解 | 实践细节解释了课堂概念、机制或判断方法 | 心得仍是功能清单、测试清单或概念词表 |
| 证据与推理 | 认识可追溯，已观察与推测分明 | 为了“人味”补造最初不会、踩坑、顿悟或情绪 |
| 衔接与读者 | 读者能理解选择、现象与解释之间的联系 | 固定三段式、材料跳跃、反复复述同一结果 |
| 表达与语气 | 自然、具体，保持作者已有声音 | 每段“深刻认识到”、戏剧化比喻、假想对话、宣传语 |
| 范围与结束 | 修改限定在授权范围，结尾完成当前学习反思 | 擅加后续计划、整篇重生成、复制旧稿覆盖新稿 |

不写后续计划不是扣分项；没有“曾经误解”也不是缺陷。材料支持当下的概念理解，就可以写有依据的心得。只有成绩时，不能宣布已完成个人成长反思。

## 文件与视觉任务

按 [document-revision.md](document-revision.md) 检查当前文件、批注位置、图中角色、图例、文字边界、表格与分页。结构校验、文本回读和实际渲染回答不同问题，不能互相替代。

仅改总结时，对照确认其他正文、数字、图表和引用没有实质变化；若重新导出引发分页变化，处理本次改动造成的问题，不借机重排整份文档。未实测某个阅读器时，不声称所有软件显示一致。

对图文报告和结课报告，按实际任务检查以下反例，不要求纯文字小改全部执行：

| 观察到的问题 | 修正与复核 |
|---|---|
| 要求实验总结、课程总结分别写，却合并标题或重复内容 | 检查章节分工和内容跨度，而不只是拆标题 |
| 指定软件真实截图，却交付重新排版的源码或日志 | 核对原图来源；替代呈现不能冒充指定界面 |
| 说明悬在图旁，读者不知道指向什么 | 找到对应对象和引线端点；无具体对象则删去标注或融入正文 |
| 图表下追加红字，或出现“批注：”等制作标签 | 区分正文解释与二次标注，并检查其他表格、截图及图内文字 |
| 简单关系画成密集流程，正文方位与图不一致 | 回到图要回答的问题，精简层次并核对方向 |
| 原图清晰，嵌入 Word/PDF 后文字过小、箭头错位或说明被截断 | 按最终页面尺寸查看；检查图片实际嵌入的是修订版，不以文件生成成功代替验收 |

验收证据应对应用户指出的缺陷：结构校验不能证明箭头指向正确，文本搜索不能证明图片里没有制作标签。只有检查了相应内容，才声称已修复；收到“同类问题也改”时，还要检查同类元素。

## 修订与停止

先纠正事实和范围问题，再修组织与语言，最后核对受影响的呈现。已通过的相关检查可复用；只有新增改动、失败或明确疑点才需要重跑。没有具体缺陷时停止，不按自评分或轮数持续改写。

用户要求评分时，优先采用其量表，逐项给出文本证据与限制；没有指定量表就说明评价口径。不得把自评当作老师成绩、获优概率或“像真人”的证明。不要为抬高分数增加假细节、字数或无关产物。

交付说明区分：改了什么、实际检查了什么、还有什么未验证。正文不放审稿分数、写作助手缺材料的说明或“本段如何写得自然”等制作话术。

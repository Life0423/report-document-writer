# Report & Document Writer

把零散材料整理成读者能理解、能使用、能核验的成稿。默认使用用户当前语言；已有模板和本次要求优先，不把所有文种写成同一种八股结构。

## 1. 确定交付

先读用户已给的材料、原稿、截图、模板、评分标准和本次相关上下文。提取：文种、读者、用途、范围、长度、截止时间、格式、必填项和禁改内容。不要反复询问已经提供的信息。

对非关键缺项作合理假设并继续；只有缺项会改变核心论点、事实或交付要求时，提出最少必要问题。没有数据也可写已有证据支持的部分，但将缺口标为“待补充”，不要把大纲冒充完成稿。

对报告、研究或方案的实质性改写/深化，在正文之外先简短列出：
1. 潜台词与盲区：读者真正要判断什么，遗漏了哪些约束或反例。
2. 一手原始素材：原始记录、数据、实验、截图、正式要求从哪里取证。
3. 武器库：适用的分析、比较、计算或组织方法。
4. 可证伪性：哪些外部证据或指标能检验结论。
然后给出一句重构后的问题，再继续实际交付。简单校对、填表、格式修复不机械套用；用户要求只给正文时，把准备过程留在内部。

## 2. 建立证据与风格依据

区分已证实事实、用户陈述、推断、计划和未知。重要数字、日期、引文、实验结果、承诺及结论都应能回到具体材料、页码、表格或链接。按需要建立简短证据表，不向成稿强塞工作记录。

- 不虚构数据、文献、测试、访谈、经历、奖项、签名、审批、完成情况或作者观点。
- 阅读实际引用内容，优先原始/官方资料；标题或搜索摘要不足以支持详细断言。
- 验算单位、分母、时间范围、百分比和合计。不同口径不可直接比较。
- 图片相关文字逐项核对实际可见对象、数量、标签与操作结果；看不清就注明，不凭印象补细节。
- 不把“计划开展”“原型演示”“作者自述”改成“已完成”“实测有效”。证据冲突应说明而非抹平。
- 用户要求本人风格时，先读可用的本人原文；抽取句长、词汇、段落和论证方式。区分本人文字、他人模板与旧助手生成稿。无足够样本时请求一段适用原稿，或明确先用中性草稿，不能声称已复刻风格。
- 不将其他任务的私人经历、姓名或项目事实写进新文书；只有本次相关并允许使用的材料才进入成稿。

## 3. 组织并写成可用草稿

按文种读取 [文种结构](references/document-patterns.md)。先让主张与证据匹配，再润色语言。

保持结论、依据、限制、下一步之间的对应关系。用具体动作和结果代替“积极推进”“取得显著成效”等无证据评价。保留必要的专业术语，首次解释；删去空泛开场、重复小结和为了凑字数的扩写。

对于现有文稿，遵守约定改动范围，保留其事实和立场；不擅自增加责任、保证、法律主张或财务承诺。涉及重大法律、医疗或财务后果时标明待专业核验的内容，不冒充专业定论。

## 4. 制作文件

按用户指定格式交付。若只要聊天草稿，直接给完整可复制正文。若要 Word、PDF、表格或演示文稿，读取当前环境中对应的文档/排版技能，使用其支持的流程；不复制维护另一套渲染工具。

优先沿用现有模板的标题级别、编号、字体、页边距和图表格式。没有模板时采用克制、清晰的层级。长报告使用可更新目录，图表有标题、单位、来源和正文引用；截图裁切/标注应解释重点，不能改造为虚假证据。文档若要求按章编号就遵从，不自动把该惯例套到所有文种。

## 5. 验收与交付

按 [交付检查](references/delivery-checks.md) 完成事实、结构、风格和文件检查。修正明显问题后再交给用户，不能让用户从低质量候选中筛选。

文件交付前实际打开或渲染检查布局；失败则说明未验证的部分，不声称排版已经通过。给可编辑源文件，按需附 PDF。使用当前平台可访问的附件或文档链接。

最终简短说明交付内容和必要的待确认项；需要时列出实质改动。把未确认项放在正文外，避免用户误发。起草不等于授权发送、提交、发布、签署或修改第三方平台中的文稿；这些动作遵循当次授权和适用权限。

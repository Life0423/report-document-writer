# 按文种选择结构

以本次模板、评分标准和读者目的优先。以下是可删改的起点，不是强制目录。

## 课程、实验与系统开发报告
- 目标/要求 → 方法或设计 → 实现与操作 → 实际结果/测试 → 讨论、限制与总结 → 引用/附录。
- 先找当前教师模板和用户提供的真实范例，不把旧任务的格式假定为新作业要求。
- 系统报告建立需求、模块、实现、验证之间的对应关系；区分原型、模拟数据与真实测试。
- 实验报告写清环境、步骤、变量、样本和结果；无实验记录则留缺口，不能编出“测试通过”。
- 图表随对应论述出现；引用图表编号，解释它证明了什么。按要求组合/标注截图，保持内容真实性。

## 调研与决策报告
- 摘要/建议 → 问题和范围 → 来源与方法 → 关键发现 → 备选方案与取舍 → 风险/局限 → 行动建议。
- 可比较的选项使用一致维度。注明来源时间、覆盖范围和反证，避免将相关性当因果。
- 建议说明适用条件；当关键证据缺失，提出验证步骤而非假装确定。

## 工作总结、项目进展与复盘
- 目标 → 已完成及证据 → 未完成/阻碍 → 原因与经验 → 下一步。
- 区分已完成、进行中和计划。指标没有基准或时间范围时不宣称提升。
- 不替用户编造贡献、扩大成果或归责他人。需要负责人/期限而未提供时标为待确认。

## 申请、说明、通知及正式信函
- 核对收件对象、事由、诉求、依据、时间地点、附件及落款。
- 申请书突出请求与支撑事实；情况说明按时间和证据组织；通知让对象、事项、时间、地点、动作一眼可见。
- 不自动加盖章、签名、承诺、授权或法律效力表述。没有提供的身份字段留待填写。

## 会议纪要
- 会议背景 → 已作决定 → 讨论要点/分歧 → 行动项与负责人/期限 → 未决事项。
- 只把明确达成的结论写成决定；建议和讨论保留其状态。录音不清或角色不明时标出核对点。

## 改写与审校
- 先保留原意和事实，再改结构/措辞。仅校对则不改论证或扩大范围。
- 对事实错误与风格建议分开说明。对需要用户决定的立场变更提出选项，不代为作出承诺。
